# v0.3.4 本地修复版

此版本用于修复自动连接结束后提示“临时微信仍在运行”的问题，安装包仅在本地生成，尚未发布到 GitHub Release。

- 直接启动的临时微信可能不在系统应用列表中。先请求应用正常退出，再对精确临时应用路径下的进程发送 `SIGTERM`，并处理调试暂停状态。
- 每次发送信号前重新核对用户、可执行文件路径及进程启动时间，避免 PID 被复用后误操作其他进程。保留退出超时，不使用按名称批量结束或 `SIGKILL`。
- 临时进程退出失败时，保留先前的取钥结果、验证数量和原始失败原因；区分进程仍在运行与无法核实进程状态。
- 增加“临时微信仍在运行”的手动处理步骤，详见 [连接操作指引](../connection-guide.md)。

回归测试使用人工进程，覆盖系统应用列表中没有登记的进程、暂停状态、辅助进程、原版及相邻目录进程排除、PID 复用、退出超时和取钥结果保留。真实微信登录和原问题设备仍需复测。

44 项 Swift 测试分别在 arm64 和 Rosetta x86_64 下通过，包含实际启动并暂停人工进程的退出测试。详见 [验证记录](../validation.md)。
