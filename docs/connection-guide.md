# 微信登录后未继续连接 / 本地密钥操作指引

适用范围：本工具支持的 macOS 微信 `xwechat_files/<账号>/db_storage` 数据布局。仅处理本人有权访问的本机账号。

## 一、登录后怎样继续

1. 在微空间中扫描本机微信，打开「连接聊天索引」，确认选择的账号目录。
2. 保存微信草稿，再点击「自动连接所选账号」。工具会正常退出微信、创建临时副本并启动连接窗口。
3. 在临时微信中完成手机确认，确认登录的是上一步选择的账号。登录完成不等于索引连接完成。
4. 打开联系人、含有图片的聊天，并向上查看较早的历史消息，让微信实际打开联系人库、图片资源库、硬链接库及消息分片。只停在会话首页，可能无法加载全部数据库。
5. 回到工具查看「已验证 X/Y 个加密索引」及「等待」的数据库名。取齐后工具会自动关闭临时微信并创建只读索引；不需要再点击登录或连接。
6. 本轮等待上限约 4 分钟。失败时，连接窗口会保留数量、缺失数据库和原因；已验证的部分密钥会保留，再次自动连接会复用有效部分。

临时微信会正常联网，并可能更新原账号的登录状态和缓存；仅用于登录、加载聊天。连接时不要再启动已安装的微信。

### 提示“临时微信仍在运行”怎么办

此提示表示临时窗口或辅助进程尚未退出；单凭旧版这条提示，不能判断此前是否已经取齐密钥。

1. 回到这次工具打开的临时微信窗口，按 `⌘Q`，等待窗口退出。
2. 如果看不到窗口，打开「活动监视器」，搜索 `WeChat`。双击候选进程，在「打开的文件和端口」中核对错误提示里的完整临时路径，尤其是 `KeyCapture/<本次 UUID>/WeChat.app/`。只对路径匹配的临时进程点击停止按钮，选择「退出」。系统列出的原版 `/Applications/WeChat.app/` 属于另一个位置。
3. 回到工具再次点击自动连接。有效密钥已保存时会复用，不必点击“忘记账号连接”。旧临时进程尚在时，先处理完它再重试。

v0.3.4 修正了直接启动的临时副本可能不在系统应用列表中、因而收不到原先退出请求的问题。新逻辑先请求应用退出，随后对核实路径、用户及进程启动时间的临时进程发送 `SIGTERM`；若其处于调试暂停状态，再让该同一进程继续，以处理退出信号。不会按微信名称批量结束进程，也不使用 `SIGKILL`。若退出失败，会保留取钥数量或原始失败原因，并保留临时目录供核对。

## 二、一直停在 0/Y，或者窗口很快关闭

- v0.3.4 及更早版本提示“临时微信无法继续运行”时，可能是工具误判旧 LLDB 的运行状态，并非已确认权限拒绝。v0.3.5 改为处理实际状态事件，同时兼容旧版 `process still running` 和新版 `process already running`，并使用旧 LLDB 支持的解除调试接口。
- 失败后在连接面板点击「复制连接诊断」；关闭错误弹窗后，也可以展开本地密钥指引找到同名按钮。诊断包含工具、微信、macOS、LLDB 版本、目标架构、验证数量、结构化错误与退出状态，不包含密钥、聊天正文、绝对文件路径或原始调试错误文本。请提供此诊断以定位异机兼容问题。
- 检查所选账号与临时微信中登录的账号一致。多账号不会共用密钥；微信密码、手机验证码、`wxid` 都不是数据库密钥。
- 首次需要 Xcode 或 Command Line Tools，可在终端执行 `xcode-select --install`。完成安装后重试。
- 若 macOS 显示开发者工具访问提示，请按提示授权；若提示拒绝调试，检查「系统设置 → 隐私与安全性 → 开发者工具」中实际列出的请求程序。只处理系统实际显示的授权项。
- 新实现为临时副本显式保留原微信的容器主目录。旧实现重签后移除了沙盒环境，有可能使临时微信使用另一个数据目录，出现登录成功但没有匹配密钥的情况。此修复已用人工程序验证目录传递，仍需在发生问题的设备上复测实际微信。
- 若联系人、图片和历史消息都打开后仍为 0，可能是微信构建使用了不同的取钥路径。当前实现不能保证兼容所有微信版本。请记录工具版本、macOS 版本、芯片类型、微信版本/构建号、验证数量和错误代码；无需提供聊天内容或密钥。
- 有少量缺失时，消息分片可能属于很久以前的历史聊天；可再次连接并查看更早的聊天记录。没有取齐前不会用不完整的索引启用按消息清理。

### 没有完整 Xcode，怎样确认开发工具

完整 Xcode 不是自动连接的必需条件，单独安装 Command Line Tools 即可提供所需开发工具。先在终端运行下面三条只读检查命令：

```sh
xcode-select -p
xcrun --find lldb
xcrun lldb --version
```

若输出 `/Library/Developer/CommandLineTools`、LLDB 路径及版本，说明工具已存在。若提示没有开发工具，执行 `xcode-select --install` 并完成系统安装提示。若已有工具与系统版本不兼容，在系统设置的「软件更新」中检查适配当前 macOS 的 Command Line Tools 更新。无需为了本工具安装完整 Xcode，也不要仅凭 `child_resume_failed` 就推断为授权问题。[Apple 安装和更新说明](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools)

若诊断显示 `breakpoint_unresolved`，表示当前开发工具未能解析取钥观察点，需要核对开发工具与系统兼容性；继续打开聊天无法补救这一问题。若有明确的 `debug_resume_denied`，再检查相应的开发者工具授权。

## 三、找到本机已经获取的密钥

在「连接聊天索引 → 登录后未继续连接 / 获取本地密钥指引」点击「定位所选账号的本地密钥…」。Finder 会选中该账号的 `keys.json`。

也可以在 Finder 按 `⇧⌘G`，输入：

```text
~/Library/Application Support/WeChatStorage/Connections/
```

每个散列命名的子目录对应一个「数据根目录 + 账号」，其中：

- `keys.json`：已获取并通过数据库页校验的本地密钥，可能尚不完整。
- `connection.json`：成功连接后才生成的连接记录，包含账号目录标识和索引快照位置。

优先使用应用内定位按钮，避免选错账号。不要发送或上传 `keys.json`，也不要复制到另一个账号目录覆盖。若没有此文件，表示尚未保存过密钥；创建一个空文件或填入微信密码无法替代取钥。

## 四、手动导入已有密钥

1. 准备属于本机所选账号、与当前原始数据库匹配的本地 JSON 文件。自动连接保存的 `keys.json` 可直接导入；从已有本地工具导出的文件须符合下面的格式。
2. 用 `⌘Q` 正常退出微信及临时微信窗口。
3. 在工具中选定对应账号，展开「高级：手动导入」，点击「选择本地密钥并连接…」，选择 JSON。
4. 工具会复制并解锁必需的数据库，建立索引；密钥错误或缺失时会中止，并说明缺少哪个库。

示例仅展示结构，下面的占位文字须替换为实际密钥，不能直接使用：

```json
{
  "keys": {
    "contact/contact.db": {"enc_key": "此数据库的64位十六进制原始密钥"},
    "message/message_resource.db": {"enc_key": "此数据库的64位十六进制原始密钥"},
    "hardlink/hardlink.db": {"enc_key": "此数据库的64位十六进制原始密钥"},
    "message/message_0.db": {"enc_key": "此数据库的64位十六进制原始密钥"}
  }
}
```

每个实际存在的 `message/message_<数字>.db` 分片都需要对应密钥。数据库可能使用不同密钥，不能假设一个密钥适用于所有库。导入器也接受路径直接映射到密钥字符串，以及 96 位十六进制的「32 字节原始密钥 + 16 字节盐」格式。64 位表示 64 个十六进制字符（32 字节），不是 64 字节，也不是登录密码。单独提供 `salt` 字段不能代替有效密钥。

此导入功能使用你已有的有效密钥；它不提供独立于自动连接机制之外的万能取钥方式。

## 五、在终端重试并查看进度

这会运行同一套自动连接流程，适用于检查图形界面看不到的进度，不能绕过微信版本兼容问题。

先正常退出微空间，保存微信草稿，再在终端执行：

```sh
/Applications/微空间.app/Contents/MacOS/微空间 \
  --connect-auto "$HOME/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/实际账号目录名"
```

将「实际账号目录名」替换为所选账号目录的真实名称，保留双引号。若数据搬到了其他位置，换成对应的账号目录绝对路径；其下应有 `db_storage`。使用单个账号目录可以避免多账号选错。

命令会打开临时微信，仍需按第一节完成登录和加载。终端输出阶段、验证数量、缺失数据库及失败说明，不打印密钥。成功的密钥保存位置与第三节相同；成功后退出终端流程，重新打开工具，扫描同一数据根目录并选择同一账号，再点击自动连接即可复用密钥。先前扫描的是整个 Data 目录时，连接缓存的命名空间不同；也可按第四节导入此次生成的 `keys.json`。

## 技术依据与验证范围

容器主目录修复依据 Apple 的 CoreFoundation 实现：`CFFIXED_USER_HOME` 会参与框架主目录解析。实现只为临时微信子进程设置此值，不改变登录用户的 `HOME`、原版微信签名或系统保护。[Apple CoreFoundation 源码](https://github.com/apple-oss-distributions/CF/blob/main/CFPlatform.c)

人工取钥测试覆盖 arm64 和 Rosetta x86_64；这些检查不等同于在真实微信账号上完成登录取钥。异机问题仍需使用修复后的版本复测。

v0.3.5 额外使用 Command Line Tools 14.3.1 / LLDB 1403 实际运行 Intel 人工多线程取钥程序，验证旧版事件与解除调试接口。旧 LLDB 无法解析测试机 macOS 26 的系统共享缓存符号，因此该兼容测试使用人工程序内的同 ABI 入口，再调用真实 CommonCrypto；该测试验证事件处理，不代表旧工具链可解析任意系统或微信的符号。现行工具链的 arm64 / x86_64 测试仍直接观察系统 CommonCrypto 入口。实现依据见 [LLDB 状态事件 API](https://lldb.llvm.org/python_reference/lldb.SBProcess-class.html) 和 [LLVM 17 恢复状态源码](https://github.com/llvm/llvm-project/blob/release/17.x/lldb/source/Target/Process.cpp)。
