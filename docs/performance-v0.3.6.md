# v0.3.6 大账号性能与共享附件处理

## 扫描范围

默认只扫描 `~/Library/Containers/com.tencent.xinWeChat/Data` 及其中内容；另统计微信应用包。手动选择时扫描所选根目录。不会递归全磁盘，不跟随符号链接或跨磁盘卷。扫描读取文件元数据，索引解析可能读取附件内容做校验。

## 本次改动

| 场景 | 原先开销 | 实施方案 |
| --- | --- | --- |
| 扫描 | 每个文件重复 realpath 解析父目录、频繁汇报进度 | 每个目录缓存规范路径，复用资源属性键集合；进度最多约每 150ms 汇报一次，保留最终进度 |
| 连接后解析索引 | 每条文件/视频消息遍历全部附件，同一内容反复读取校验 | 为当前账号构建文件名/视频标识索引；本轮连接缓存已校验的物理文件 MD5，使用前后仍核对文件身份 |
| 分析账号 | 主线程构建所有聊天、消息及附件统计 | 后台计算 Analysis、消息分组与排序、未匹配附件分组和汇总，再将结果交给界面 |
| 切换聊天 | 反复从整个账号筛选、排序消息 | 按聊天 ID 获取预先排序的消息分组，在后台应用类型、日期、关键词过滤 |
| 消息与未匹配附件列表 | 直接提交全部结果，筛选随界面刷新重复执行 | 筛选结果缓存；默认展示 200 项，可每次增加 200 项；搜索延迟 150ms 合并输入，过期结果不回填 |
| 未匹配附件统计 | 每次刷新重新筛选全部账号附件、求和 | 按账号缓存列表和总大小；选择大小按已选路径查询计算 |
| 清理预览 | 主线程核对大量文件及父目录 | 后台建立清理计划，界面显示操作进度 |

“选择当前筛选结果”会选取该筛选下全部结果，包括尚未点击加载更多的项目。列表分页只限制显示，不会截断清理引用校验。聊天切换会清除消息选择，清理选项按账号隔离。

## 硬链接与其他引用

聊天与消息中，硬链接附件可以移除所选路径。默认仍保护同一路径被未选消息引用的附件。勾选“同时移除本账号其他路径和消息引用的同一附件”后，加入本次扫描中同账号、同物理文件的其他附件路径，允许处理未选消息的引用。清理预览列出完整路径，并要求再次确认。不会扩展到其他账号、数据库、未扫描位置或仅凭内容相同的独立副本。

附件仍然移入废纸篓，未清空前不释放其数据；扫描外若还有硬链接，清空后也未必释放全部空间。

## 验证与边界

arm64 与 Rosetta x86_64 的 47 项 Swift 检查分别通过，含共享路径扩展、跨账号保护、清理恢复和异步预览流程。人工 1000 聊天、100000 消息的分析与分组在开发机测得约 0.19–0.21 秒；Intel 安装应用另通过 19 项人工演示布局与交互检查。这是内存分析检查，不代表 100GB 真实微信账号的扫描、解密或界面帧率。

首次解密快照仍需要复制、读取数据库；首次校验每个候选附件仍需要读取其内容。本轮没有将全部原始索引改造成磁盘分页数据库，内存占用仍随账号消息量增长。需要在原 Intel 设备和真实大账号上复测端到端耗时。
