# 验证记录

## v0.3.9 整目录清理与图片

53 项 Swift 检查分别在 arm64 与 Rosetta x86_64 下通过，覆盖目录移动与恢复、无全目录重扫、普通/XOR/V1/V2 图片解码、错误密钥和畸形长度。微空间 Intel 安装应用完成 22 项人工界面检查，包含真实人工 PNG 的缩略图显示与 Finder 入口。消息和其他文件的加载更多已移到底部。V2 密钥获取仍由用户在本地提供，wxgf 等未支持格式会提示；未使用用户真实聊天内容或图片测试。

## v0.3.8 全局加载

49 项 Swift 检查分别在 arm64 与 Rosetta x86_64 下通过。21 项演示布局与交互检查通过，新增主窗口与连接面板加载层，验证忙碌时侧栏点击无效、关闭按钮禁用，完成后侧栏和关闭按钮恢复。菜单入口由 busy 状态禁用，面板与剪贴板操作另有模型层入口检查。微信窗口和系统授权提示不受本工具内容遮罩影响。

## v0.3.7 聊天清理口径

48 项 Swift 检查分别在 arm64 与 Rosetta x86_64 下通过。新增无消息映射时预览路径、逻辑大小与聊天统计严格一致及跨账号拒绝检查。Intel 安装应用通过 19 项演示布局与交互检查。Finder 路径检查由代码限制在所选账号范围内，尚未在用户真实账号上手动打开验证。

## v0.3.6 性能与共享附件验证

- 47 项 Swift 检查在 arm64 与 Rosetta x86_64 下分别通过。包含共享物理文件路径扩展、默认消息引用保护、跨账号保护、清理恢复，以及后台预览完成后执行清理。

## v0.3.5 LLDB 兼容验证

- 18 项 Python 测试通过，覆盖新旧运行状态提示、自动恢复的启动事件、重复暂停、其他进程事件、权限拒绝、进程退出、异常停止及完成后的解除调试。
- 在独立安装的 Command Line Tools 14.3.1 / LLDB 1403 下复现旧版本 helper 的 `child_resume_failed`；旧事件轮询方式也会出现未读取到观察点而超时的情况。修复后的 Intel 多线程人工取钥程序已完成密钥校验、解除调试及提前退出检测。
- 旧 LLDB 不能解析测试机 macOS 26 的系统共享缓存符号。旧工具链夹具因此提供本地同 ABI 入口，并调用真实 CommonCrypto；它用于验证事件与 API 兼容性，不验证旧 LLDB 对当前系统或微信符号的解析能力。
- 现行 LLDB 的 arm64 和 Rosetta x86_64 夹具仍直接观察系统 CommonCrypto。夹具增加四个线程的多次 PBKDF 调用，以覆盖反复暂停和恢复。
- 45 项 Swift 测试分别在 arm64 和 Rosetta x86_64 下通过，新增账号诊断隔离、私有文件权限，以及诊断中排除原始进程输出、密钥和绝对路径的检查。

用户报告的环境为 Intel、macOS 15.8.1、微信 4.1.15、未安装完整 Xcode。该系统和真实微信登录尚未完成本机回归，人工程序通过不能视为用户账号已可连接。

## v0.3.4 临时微信退出验证

- 44 项 Swift 测试分别在 arm64 和 Rosetta x86_64 下通过。
- 新增 6 项退出流程测试，覆盖未登记到系统应用列表的主进程及辅助进程、原版及相邻目录排除、PID 复用、暂停状态、有限等待和原始取钥结果保留。
- 实际进程测试在人工临时应用目录复制并启动 `/bin/sleep`，确认不在系统应用列表中，将其暂停后通过新退出流程关闭，并确认另一个无关进程仍在运行。两个架构均通过该测试。
- 本次未修改 Python 取钥或附件界面逻辑；沿用 v0.3.3 的相关验证记录。

这些检查复现的是缺失退出请求和暂停进程的情形，未替代真实微信及报告问题设备的回归。仍拒绝退出的临时进程会保留路径并报告；不会把进程状态未知报告为已成功退出。

- 9 项 Python 测试通过。人工 Foundation / CommonCrypto 程序在 arm64 和 Rosetta x86_64 下验证：临时子进程获得指定的容器主目录、Documents 路径一致、实际捕获并校验密钥、提前退出时报告缺失数据库，事件不包含密钥。

## 界面检查

原生布局检查渲染完整 MainView，包含固定导航、标题、提示和操作栏。覆盖 1080 × 700、1240 × 800、1440 × 900，标准标题栏窗口、长名称、空结果、共享附件、清理后切换聊天及首页。

通过向演示窗口投递鼠标事件验证聊天行、复选框、返回和侧栏切换，以及共享附件勾选后生成清理计划。完成清理后检查原生系统弹窗的标题、废纸篓说明和 Finder 按钮，并点击「知道了」继续操作。

这些检查不等同于全部主窗口操作的人工作业回归。Intel、不同 macOS 主版本和不同微信构建仍需分别验证。

v0.3.2 从安装文件取出两个架构的应用后，分别通过 19 项布局与交互检查；x86_64 检查在 Rosetta 下运行。随包 Intel SQLCipher 另验证了人工加密数据库的写入和读取。

## 发布包检查

- 全尺寸 `.icns`（16–1024 像素）及应用图标配置。
- 应用、SQLCipher 和动态库的实际 Mach-O 部署下限。
- `codesign --verify --deep --strict`、随包 SQLCipher 启动。
- DMG 可只读挂载、应用完整性及 Applications 安装链接。
- 从安装文件复制应用至独立验证目录后运行。
- DMG / ZIP 的 SHA-256 和 GitHub Release 附件回读校验。

当前发行方式为 ad-hoc 签名预览包，未启用 Hardened Runtime，未做 Developer ID 签名或 Apple 公证。v0.3.2 发布包的应用、SQLCipher、Zstandard 实际部署版本均为 14.0；OpenSSL 静态链接到 SQLCipher。源码归档固定版本并校验 SHA-256，构建过程不修改 Homebrew。分别提供 arm64 和 x86_64 安装包，并逐组件检查架构，拒绝混装依赖。

运行验证在 macOS 26 的 Apple Silicon 真机完成；x86_64 应用、SQLCipher 和取钥测试程序在 Rosetta 下验证。Intel 真机及 macOS 14 / 15 尚未实机回归。各架构的 `.compatibility.json` 明确记录该限制。
